# 行业与技术知识学习助手 PRD

## 1. 文档信息

- 产品暂定名：Knowledge Quest（知识征途）
- 版本：v1.0
- 日期：2026-09-30
- 产品形态：Windows 本地桌面应用
- 目标阶段：可长期个人使用的 MVP

## 2. 产品概述

Knowledge Quest 用于系统学习一个新行业或一项技术知识。应用将调研、分析、资源筛选、学习规划和能力验证组织成一条可追踪、可回退、可反思的 Skill 工作流，而不是提供一次性的聊天回答。

用户通过 AI 访谈创建学习项目。系统按照八个 Skill 依次生成成果，每次生成均经过结构化反思、证据检查和自动修订。只有用户确认后的成果，才会成为后续 Skill 的正式输入。

## 3. 产品目标

### 3.1 核心目标

1. 快速建立一个行业或技术领域的整体认知框架。
2. 将搜索、阅读、笔记、计划、练习和考试统一在一个项目中。
3. 让 AI 输出具备来源、证据等级、反思记录和版本追踪。
4. 将一次性 Prompt 转化为可复用、可组合、可测试的 Skill。
5. 通过学习阶梯、任务和考试反馈形成持续学习闭环。

### 3.2 成功指标

- 用户可在 10 分钟内完成项目创建并开始第一个 Skill。
- 八个 Skill 均可独立运行、重新运行并保存历史版本。
- 所有正式成果均包含反思摘要和质量评分。
- 关键事实和结论可追溯到来源，或明确标记为推断。
- 用户可以从项目创建走到首次考试，全流程无阻断性错误。
- 项目能够完整导出，并可从备份恢复。

### 3.3 非目标

- MVP 不提供多人协作、组织权限和团队知识库。
- MVP 不提供签到、积分商城或社交排行榜。
- MVP 不在本机训练大模型。
- MVP 不替代专业认证、正式教育或专家意见。
- MVP 不支持移动端和 macOS。

## 4. 目标用户与场景

### 4.1 目标用户

- 需要快速理解陌生行业的创业者、投资者、产品经理和求职者。
- 需要系统学习新技术栈的开发者和技术管理者。
- 希望统一管理资料、知识、计划和复习的个人学习者。

### 4.2 典型场景

- 两周内理解储能行业的价值链、商业模式、关键玩家和风险。
- 从零开始学习大语言模型应用开发，并完成一个小型项目。
- 基于研究报告和网页建立结构化知识框架。
- 通过自适应考试识别薄弱知识点并触发返工。

## 5. 已确认的产品决策

- 同时支持行业知识和技术知识。
- 八个 Skill 按固定顺序展示，允许用户主动跳过。
- 创建项目时由 AI 对话访谈用户。
- 支持联网搜索和用户资料导入。
- 默认使用五视角，允许 AI 按主题调整专家角色。
- 采用“对话引导 + 项目看板”双界面。
- 考试题量和难度可配置，并记录知识点掌握度。
- 第一版仅支持 Windows，支持多个独立项目。
- 使用 OpenAI 兼容接口，由用户配置地址、密钥和模型名称。
- 默认提供搜索能力，高级设置可切换搜索服务。
- 支持 PDF、网页、Markdown、TXT 和粘贴文本。
- 支持导出 Markdown、PDF 和完整项目备份包。
- 不提供系统学习提醒。
- 界面采用游戏化学习地图，但不依赖积分、签到和排行榜。

## 6. 产品原则

1. **确认优于自动传递**：只有用户确认的版本才进入下游 Skill。
2. **证据优于流畅表达**：关键结论必须有来源或明确标注为推断。
3. **反思优于一次生成**：每次正式生成必须经过质量审查和修订。
4. **本地优先**：项目、笔记、配置和历史版本保存在本地。
5. **用户可控**：用户可跳过、返工、编辑、锁定或重新生成步骤。
6. **结构化优先**：输出同时包含可阅读成果和机器可处理的数据。

## 7. 工作流模型

### 7.1 Skill 状态

- locked：前序步骤尚未处理。
- ready：可以开始。
- running：正在检索或生成。
- reviewing：正在反思和检查。
- needs_input：需要用户提供信息。
- draft：草稿已生成，等待确认。
- confirmed：用户已确认，可传递给下游。
- skipped：用户主动跳过。
- stale：上游发生变化，需要重新评估。
- failed：执行失败，可重试。

### 7.2 顺序与依赖

1. Skill 按固定顺序显示。
2. 当前 Skill 确认或跳过后，下一个 Skill 解锁。
3. 跳过时记录原因，并将信息缺口传给下游。
4. 下游只使用上游最近一次 confirmed 版本。
5. 上游 confirmed 版本变化后，受影响的下游结果标记为 stale。
6. stale 结果可查看，但不得继续作为正式输入。

## 8. 八个业务 Skill

### 8.1 五视角研究 perspective-storm

目标：从互补或冲突的角色建立主题全景。

默认角色：实践者、学者、怀疑者、经济学家、历史学家。AI 可根据主题替换或增加角色，但必须解释原因。

输出：各角色立场、最强证据、独有问题、初步共识、冲突、关键术语和待确认问题。

### 8.2 矛盾图谱 contradiction-map

目标：找出直接冲突、证据差异、共识和知识盲区。

输出：冲突双方及依据、证据强弱、适用条件、化解冲突的关键问题、多视角共识、盲区，以及图谱节点和关系数据。

### 8.3 综合简报 research-brief

目标：形成便于快速掌握主题的研究简报。

输出：一段话总览、按可靠性排序的发现、隐含关联、与用户身份相关的行动建议，以及可能改变整体理解的前沿问题。

### 8.4 同行评审 peer-review

目标：审查综合简报的可靠性、完整性和偏差。

输出：关键发现的可靠性评分、评分理由、遗漏信息、视角失衡、新角色可能造成的变化，以及后续研究清单。

### 8.5 资源筛选 resource-curator

目标：自动搜索或评价用户提供的学习资源，并形成学习路线。

输出：适用对象、推荐理由、使用方式、预计时间、关键知识点、被高估之处、可跳过部分、可信度、时效性和排序后的资源路径。

### 8.6 学习阶梯 learning-ladder

目标：将主题拆分为五级能力路径。

默认等级：完全初学者、基本理解、实际使用者、问题解决者、自信的实践者。

每级输出：目标、概念、技能、掌握表现、关注重点、晋级里程碑、练习或小项目、常见错误和自测问题。

### 8.7 二八学习计划 pareto-study-plan

目标：找出产生主要实际效果的核心概念和技能，并形成计划。

输出：核心 20% 知识、默认十次课计划、每课目标、概念、练习、资源、预期结果、复习题、每日任务和最终最小实践项目。

### 8.8 自适应考试 adaptive-exam

目标：通过逐题问答确认真实理解，并反馈到学习系统。

输出：动态难度题目、逐题评分和反馈、最终得分、强项、薄弱项、复习计划、知识点掌握度、最终挑战题，以及对资源、阶梯和计划的返工建议。

## 9. Skill 标准接口

### 9.1 输入

- projectProfile：主题、类型、目标、水平和时间预算。
- upstreamArtifacts：已确认的上游成果。
- sources：用户资料和联网检索结果。
- userNotes：笔记、批注和人工修改。
- skillConfig：角色、题量、深度、语言等配置。

### 9.2 输出

- content：面向用户的 Markdown 成果。
- structuredData：看板、图谱、计划或考试所需数据。
- claims：关键结论及其来源关联。
- assumptions：假设和不确定性。
- openQuestions：需要用户确认的问题。
- reflection：结构化反思报告。
- handoffContext：下一 Skill 所需的最小上下文。

### 9.3 代码封装

每个 Skill 使用独立目录，包含：

- manifest：名称、版本、Schema、依赖和权限。
- prompt：任务指令和输出约束。
- rubric：反思评分标准。
- handler：检索、生成、解析和持久化逻辑。
- tests：Schema、提示词快照和典型案例测试。

## 10. 反思与自动修订

### 10.1 原则

反思是结构化质量检查，不保存或展示模型隐含思维链。用户看到的是评分、问题、证据和修改记录。

### 10.2 标准闭环

1. 生成初稿。
2. 校验输出 Schema。
3. 检查事实与引用覆盖率。
4. 检查逻辑一致性、遗漏和目标匹配度。
5. 按当前 Skill rubric 评分。
6. 生成结构化改进建议。
7. 自动修订一次。
8. 再次评分。
9. 达标后进入 draft；不达标则进入 needs_input 或保留警告草稿。

### 10.3 通用评分

- 完整性：0–100。
- 证据可靠性：0–100。
- 引用覆盖率：0–100。
- 逻辑一致性：0–100。
- 用户目标匹配度：0–100。
- 可执行性：0–100。

默认通过条件：总分不低于 75，且证据可靠性和逻辑一致性均不低于 70。Skill 可定义更严格的阈值。

### 10.4 修订限制

- 默认最多自动修订一次，防止无限循环和成本失控。
- 第二次评分仍不达标时，展示具体问题并请求用户处理。
- 缺失关键用户信息时，不允许通过猜测填补。
- 事实结论缺少来源时，应删除、降级为推断或补充检索。

## 11. 页面与用户体验

### 11.1 项目大厅

- 展示项目名称、主题类型、当前 Skill、掌握度和最近活动。
- 支持创建、归档、删除、备份和恢复。
- 游戏化表现为学习地图、关卡状态和能力成长。

### 11.2 AI 创建向导

- 对话收集学习主题、背景、目标、时间和预期成果。
- AI 总结项目档案，用户确认后创建项目。
- 行业学习和技术学习使用不同访谈模板。

### 11.3 学习地图

- 展示八个 Skill 节点和状态。
- 支持进入、跳过、重新运行和查看历史版本。
- stale、failed、needs_input 使用明显视觉标识。

### 11.4 Skill 工作台

- 左侧：资料、来源和历史版本。
- 中间：AI 对话和执行状态。
- 右侧：正式成果、反思报告、笔记和确认操作。
- 人工编辑后的版本标记为 user-edited。

### 11.5 资源中心

- 支持自动搜索和用户添加资源。
- 展示来源、摘要、引用片段、访问日期、时效性和证据等级。
- 支持去重、标签和结论关联。

### 11.6 学习计划与考试

- 计划页展示课程、任务、练习、复习题和完成状态。
- 考试一次展示一道题，根据回答动态调整难度。
- 考试结束后更新知识点掌握度和返工建议。

### 11.7 设置中心

- 模型接口地址、API 密钥和模型名称。
- 搜索提供商和默认搜索参数。
- 本地数据目录和附件目录。
- 导出、备份、恢复和数据清理。
- API 密钥使用 Windows 安全存储，不写入数据库或日志。

## 12. 资料与引用

### 12.1 导入格式

- PDF。
- 网页 URL。
- Markdown。
- TXT。
- 粘贴文本。

### 12.2 来源记录

来源至少保存：标题、类型、原始位置、作者、发布日期、访问日期、摘要、引用片段、内容哈希和可信度信息。

### 12.3 结论追溯

- 每条关键结论可以关联一个或多个来源片段。
- 无来源结论必须标记为 AI 推断或用户观点。
- 来源冲突时保留不同观点，不强行合并。
- 用户可以从结论定位到支撑材料。

## 13. 数据模型

- Project：学习项目和项目档案。
- SkillRun：一次 Skill 执行及状态。
- Artifact：Skill 成果版本。
- ReflectionReport：评分、问题和修订摘要。
- Source：导入或检索的来源。
- SourceExcerpt：可引用的来源片段。
- Claim：关键结论。
- ClaimSource：结论与来源片段的关联。
- Note：用户笔记和批注。
- LearningLevel：学习阶梯等级。
- StudySession：计划中的学习任务。
- Exam：一次考试。
- ExamQuestion：题目、回答、评分和反馈。
- KnowledgeNode：知识点和掌握度。
- AppSetting：非敏感设置。
- SecretReference：Windows 安全存储中的密钥引用。

核心实体使用 UUID。Artifact、ReflectionReport 和 SkillRun 保留历史版本，不做覆盖式更新。

## 14. AI 与搜索架构

### 14.1 模型接口

- 提供 OpenAI 兼容适配层。
- 模型地址、模型名和参数由用户配置。
- Skill 不直接依赖具体模型厂商。
- MVP 中生成、反思和评分默认使用同一模型。

### 14.2 搜索接口

- 使用统一 SearchProvider 接口。
- 提供一个默认实现，并允许配置替代服务。
- 结果经过抓取、去重、元数据规范化和引用片段提取。

### 14.3 上下文控制

- 优先传递 handoffContext，不发送全部历史对话。
- 资料按需检索，避免将整个项目无差别发送到云端。
- UI 显示当前请求将发送的资料范围。
- 日志不记录 API 密钥和完整隐私资料。

## 15. 本地存储与安全

- 使用 SQLite 保存结构化数据。
- 附件保存在独立项目目录，由数据库引用。
- API 密钥保存在 Windows Credential Manager 或等价安全存储。
- 项目备份包含数据、附件、Markdown 成果和 manifest。
- 导出前可选择是否包含原始资料。
- 删除项目需确认，并优先移动至应用回收站。
- 网络请求使用 HTTPS；自定义非 HTTPS 地址时显示警告。

## 16. 导出与备份

### 16.1 Markdown

- 每个 Skill 输出独立 Markdown 文件。
- 项目根目录生成索引、来源清单和学习进度摘要。

### 16.2 PDF

- 可输出完整学习报告或单个 Skill。
- 保留标题层级、引用、图表、页码和生成日期。

### 16.3 备份包

- 使用带版本号的压缩包格式。
- 包含 manifest、项目数据、成果、反思、笔记和可选附件。
- 恢复前进行版本和完整性检查。

## 17. 非功能需求

- 支持 Windows 10/11 64 位。
- 常规本地交互响应时间低于 200ms。
- 长时间 AI 操作显示阶段状态并允许取消。
- 异常退出后，已保存成果和用户编辑不得丢失。
- 数据库迁移前自动备份。
- Skill 输出通过 Schema 校验。
- 核心业务具有单元测试和集成测试。
- UI 首先支持中文，并为国际化预留结构。

## 19. 推荐技术架构

- Tauri 桌面容器。
- React + TypeScript 前端。
- SQLite 数据库。
- Zod 或 JSON Schema 校验 Skill 输入输出。
- 本地应用服务负责文件、数据库、安全存储和网络代理。

目录规划：

~~~text
src/
  app/                 应用入口、路由和全局状态
  features/            页面级业务功能
  components/          通用 UI
  skills/              八个 Skill 定义与前端呈现
  workflow/            状态机、依赖和 stale 传播
  reflection/          通用反思与评分
  ai/                  模型适配器和上下文构建
  search/              搜索适配器
  sources/             导入、解析、切片和引用
  storage/             数据访问层
  export/              Markdown、PDF 和备份
src-tauri/
  commands/            前端可调用的本地命令
  database/            SQLite、迁移和仓储
  filesystem/          附件与导出
  secrets/             Windows 安全存储
~~~

## 20. 开发阶段

### 阶段一：工程基础

- 初始化桌面工程。
- 建立设计系统、路由和项目大厅。
- 建立数据 Schema、迁移和仓储接口。
- 建立模型配置和连接测试。

### 阶段二：Skill 平台

- 定义 Skill manifest 和 Schema。
- 实现工作流状态机。
- 实现 Artifact 版本、确认、跳过和 stale 传播。
- 实现通用反思闭环。

### 阶段三：核心学习能力

- 完成资源筛选、学习阶梯和学习计划。
- 完成资料导入和来源追溯。
- 完成笔记和学习任务管理。

### 阶段四：完整工作流

- 补齐五视角、矛盾图谱、简报和同行评审。
- 完成自适应考试和掌握度反馈。
- 完成 Markdown、PDF 和备份导出。

### 阶段五：稳定性与发布

- 测试、错误恢复、性能和安全检查。

## 21. MVP 验收标准

1. 用户可创建至少两个互不影响的学习项目。
2. AI 访谈生成项目档案，用户可以修改确认。
3. 八个 Skill 均可运行并生成符合 Schema 的 Artifact。
4. 每个 Artifact 均关联 ReflectionReport。
5. 不达标输出可自动修订一次，并展示修改摘要。
6. 用户可确认、编辑、跳过和重新运行 Skill。
7. 修改上游结果后，下游结果正确标记为 stale。
8. 用户可导入规定格式，并从关键结论定位到引用片段。
9. 资源筛选、学习阶梯和二八学习计划满足完整功能要求。
10. 考试逐题自适应，结束后更新知识点掌握度。
11. 项目可导出 Markdown 和备份包，并成功恢复。
12. API 密钥不以明文出现在数据库、导出文件或日志中。
13. 应用重启后项目状态、成果版本和笔记保持完整。

## 22. 迭代一：项目文件夹持久化与断电恢复（2026-10-01）

### 22.1 背景与目标

浏览器 localStorage 只能作为缓存，无法满足长期学习、跨浏览器打开和突然断电后的可靠恢复。本迭代为每个学习项目绑定一个用户选择的本地文件夹，并将项目档案、成果版本和恢复日志写入文件夹。

### 22.2 用户流程

1. 用户通过“创建学习项目”完成访谈后，选择或创建一个项目文件夹。
2. 项目创建成功后，系统立即写入 `project.json`、`artifacts.json` 和 `events.jsonl`。
3. 每次生成、反思、确认或项目状态变化后，自动更新项目文件夹，同时保留浏览器本地缓存。
4. 重启浏览器或 PC 后，用户点击“打开项目文件夹”，选择该文件夹即可恢复项目和历史成果。
5. 读取失败、权限被撤销或浏览器不支持文件夹 API 时，必须保留本地缓存并给出明确提示，不得清空已有项目。

### 22.3 文件格式

```text
项目文件夹/
├─ project.json       # 项目档案、Skill 状态、成果索引和掌握度
├─ artifacts.json     # 全部 Artifact 历史版本及反思报告
└─ events.jsonl       # 最近一次保存事件，供故障排查和恢复审计
```

API Key 不写入项目文件夹；仅保留在当前会话或后续桌面版的 Windows 安全存储中。

### 22.4 MVP 验收标准

- 新建项目时可以选择项目文件夹；取消选择时仍保留浏览器本地副本。
- 项目生成、确认和重启后，文件夹内可以恢复完整项目状态及 Artifact 历史版本。
- “打开项目文件夹”可以将项目重新载入项目列表并定位到上次可用 Skill。
- 写入失败不会覆盖浏览器缓存，也不会展示空项目。
- Chrome/Edge 不支持 File System Access API 时，界面能够继续使用本地缓存并提示限制。

### 22.5 后续增强

- 使用原子临时文件替换，增加 `backups/` 定时快照。
- Tauri 桌面版使用 SQLite 和原生文件权限，支持真正的后台自动保存。
- 增加项目文件夹路径显示、权限重新授权和备份恢复向导。

### 22.6 交互流程修订

- “创建学习项目”首先触发文件夹选择，文件夹选择成功后才进入 AI 对话访谈；项目 ID 在选择文件夹前生成，用于绑定目录。
- 侧栏提供独立的“打开已有项目”入口，读取所选目录中的 `project.json`，恢复项目、成果历史和当前 Skill，并同步到应用项目列表。
- 文件夹选择期间显示非阻塞状态提示；取消选择不会丢失项目，自动降级到浏览器本地缓存。
- 浏览器界面显式设置鼠标指针样式，避免文件夹选择返回后用户误以为界面失去响应。

### 22.7 系统总目录（本次实现）

- 在“模型与设置”中提供“系统数据目录”配置，用户选择一次总目录即可。
- 系统自动在总目录下创建 `projects/`，每个项目使用独立的项目子目录。
- 应用启动时扫描 `projects/` 下的 `project.json`，将历史项目自动合并到侧边栏。
- 新建项目不再重复选择项目文件夹；项目完成访谈后自动创建子目录并开始同步。
- “打开已有项目”继续支持从任意单独项目目录导入，作为总目录机制的兼容入口。
